NewScribe 用户帮助

工程格式与保存

本地工程、分享工程和 VideoScribe 导入格式的区别，以及保存、备份和恢复。

.nscribe

本地工作工程。旁边带一个 .assets 素材文件夹，适合日常编辑和快速保存。

.nspkg

单文件分享工程。图片、SVG、音频和自定义手势都在文件内部。

.scribe

VideoScribe 工程，只能导入。导入结果可能受原工程结构影响。

3. 不同工程格式#

.nscribe：本地工程#

.nscribe 是本地工作工程。它旁边会有一个同名 .assets 文件夹，用来存放图片、SVG、音频等素材。

我的工程.nscribe
我的工程.assets/

这种格式适合在本机日常编辑、频繁保存、自动保存、继续修改、快速打开等等。NewScribe的移动端不支持该格式。

.nscribe 的保存速度较快，因为只有新素材才需要写入。

.nspkg：分享工程#

.nspkg 是单文件分享包。它把工程数据、图片、SVG、音频、自定义手势和缩略图都装在一个文件里。

我的工程.nspkg

这种格式适合发给别人修改、归档、备份，可以用作在不同电脑之间搬运、协作，这能避免对方打开后缺素材。

因为它包含全部素材，文件通常会比 .nscribe 大，保存也会慢一些。移动端仅支持这一文件格式。

不过，出于版权安全的考虑，无论是.nscribe还是.nspkg，都不会保存字体文件，为了保持导出效果的一致性，请确保接收工程的一方也安装了相应的字体。

.scribe：VideoScribe工程#

.scribe 是另一款类似的软件VideoScribe的工程文件。NewScribe支持导入这种文件，但是无法保存为该格式。

请注意的是，NewScribe对.scribe 格式的有限支持是实验性质的，导入.scribe 文件可能会出现元素消失、拉伸、大小异常、机位显示异常等情况。不建议将VideoScribe上尚未完成的工程导入NewScribe继续创作。

保存、另存为和导出#

保存工程和导出视频是两件事。

保存工程是将工程保存为上述的.nscribe或.nspkg文件，这些文件不是可以播放的视频。如果需要视频，请点击“导出视频”，导出的视频为.mp4格式。

新建工程，首次保存时，NewScribe 会让你选择工程格式，并明确提示这一点。如果想更换格式或储存位置，请点击另存为。

相关效果和快捷键如下：

  • Ctrl+S：按当前工程已有格式保存。
  • Ctrl+Shift+S：另存为，可以选择 .nscribe 或 .nspkg。
  • Ctrl+E：导出视频。

NewScribe无法编辑已经导出的视频文件，也无法将视频逆向工程为可编辑的工程文件。

进一步说明：什么时候用 .nscribe，什么时候用 .nspkg#

把 .nscribe 想成“工作台”，把 .nspkg 想成“打包好的箱子”。

你在自己的工作台上创作时，工具可以摊开，素材可以放在旁边的抽屉里，取用很快。.nscribe 就是这样：工程文件负责记录排版、动画和时间轴，旁边的 .assets 文件夹负责放素材。日常编辑、反复保存、自动保存，都应该优先用它。

当你需要把作品交给别人，工作台就不能直接搬走了。对方没有你的素材抽屉，打开工程只会看到一堆红色占位框。.nspkg 把工程和素材装进同一个箱子，对方拿到一个文件就能打开，适合分享、归档和跨电脑搬运。

因此，推荐的工作习惯是：

  • 本机创作、频繁修改：.nscribe
  • 发给别人、提交审阅、长期归档：.nspkg
  • 需要视频：导出 MP4，而不是发送工程文件

.nscribe 不是“低级格式”，.nspkg 也不是“高级格式”。它们只是用途不同。把 .nspkg 当成日常自动保存格式，会在素材很多时反复重写大文件；把 .nscribe 单独发给别人，又会缺素材。

工程文件夹的结构#

一个典型的本地工程会形成这样的目录：

项目文件夹/
  我的工程.nscribe
  我的工程.assets/
    a1b2c3d4e5f6.png
    0f9e8d7c6b5a.svg
    3c2b1a0f9e8d.mp3
  我的工程.nscribe.bak

.nscribe 内部的素材记录通常只保存相对路径，例如 ./我的工程.assets/a1b2c3d4e5f6.png。因此，工程和素材文件夹必须保持相对位置。只移动 .nscribe，或者只重命名 .assets，都会导致素材找不到。

如果要整体搬动工程，最稳妥的方式是把整个项目文件夹一起复制。不要只复制工程文件。

如果只需要发送工程，使用“另存为 .nspkg”，这样就不用考虑素材文件夹。

保存、备份和恢复的关系#

每次保存 .nscribe 时，NewScribe 会写入临时文件，并在替换前保留上一版为 .bak。这样即使新文件写入失败，旧文件通常还在。

.nspkg 使用同样的原子保存思路，只是备份文件会更大，因为整个分享包都要复制一份。

备份不是版本管理。它只保留上一版，不会保留十几次修改历史。如果你需要保留多个版本，可以手动使用“另存为”，在文件名里加日期，例如：

产品介绍-2026-11-21.nspkg

对于重要项目，建议同时保留：

  • 当前工作工程 .nscribe
  • 一份分享包 .nspkg
  • 一份导出的 MP4
  • 必要时再加一份带日期的归档副本

自动保存的注意事项#

自动保存只会对已经保存过路径的工程生效。一个新建但从未保存的工程，不会凭空出现自动保存文件。

自动保存间隔可以在首选项里调整。间隔太短，频繁写盘会打扰编辑；间隔太长，崩溃时损失更多。对大多数项目，几分钟一次比较合适。

自动保存并不等同于“随时可以关机”。在导入大素材、调整大量时间轴、准备导出之前，仍然建议按一次 Ctrl+S。

.scribe 导入的限制#

.scribe 是 VideoScribe 的工程格式。NewScribe 可以尝试导入，但它不是完整兼容的 VideoScribe 编辑器，导入结果可能出现：

  • 元素位置或大小偏差
  • 机位不一致
  • 某些元素消失
  • 字体替换
  • 动画方式变化

因此，.scribe 导入更适合“参考旧工程”或“把已经完成的工程迁移过来”，不适合把 VideoScribe 里尚未完成的复杂工程直接搬来继续制作。导入后应该先预览，再决定是否继续。

文件名和路径建议#

尽量使用短而清晰的文件名，避免特殊符号和过长的中文路径。Windows 对路径长度和特殊字符的限制，可能让工程、素材或导出文件写入失败。

如果工程需要跨电脑使用，路径中不要依赖某台电脑独有的盘符或目录。.nspkg 不依赖外部路径，更适合这种情况。
